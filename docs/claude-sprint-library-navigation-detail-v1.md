# PlayVault Sprint：游戏库导航与详情页体验收口

## 1. Sprint 目标

本 Sprint 的目标是：

**把 PlayVault 的主体验从“页面菜单 + 游戏表格”调整为“左侧树状游戏库导航 + 右侧游戏详情页”。**

当前很多核心能力已经具备：

- 游戏库
- 状态
- 安装状态
- 启动游戏
- Session
- 截图箱
- 回收站
- 详情页基础信息

但它们还比较分散。本阶段不新增大功能，只把现有能力组织成更符合长期使用的结构。

## 2. 本次修改范围

本次只允许修改：

- 左侧导航 `Sidebar`
- 主布局 `AppLayout`
- 游戏库页面 `Games`
- 游戏详情页 `GameDetail`
- 游戏状态常量与状态展示
- 路由跳转方式
- 与游戏列表读取相关的 hooks

不允许大改：

- 截图箱生命周期
- 截图扫描
- 进程监听
- 游戏启动后端逻辑
- 数据库结构
- 本地游戏扫描发现逻辑

## 4. 任务拆分

### 任务 A：统一游戏状态前端显示

#### 目标

确保所有前端 UI 只使用 3 个游戏状态：

- `not_started`：未开始
- `in_progress`：游玩中
- `completed`：已通关

#### 任务内容

1. 检查 `src/shared/constants.ts`。
2. 确认 `GAME_STATUSES` 只包含这 3 个状态。
3. 检查 `StatusBadge` 是否只展示这 3 种状态。
4. 检查 `GameForm` 是否还出现：
   - 搁置
   - 弃坑
   - 已全成就
5. 检查 `Games` 页面筛选项是否只出现 3 状态。

#### 验收标准

- 前端不再出现 `搁置 / 弃坑 / 已全成就`。
- 新建或编辑游戏时，只能选择 3 状态。
- 游戏状态徽章显示正确中文文案。
- 已有 `completed / in_progress / not_started` 状态展示正常。

### 任务 B：左侧游戏库树状导航

#### 目标

把当前侧边栏中的“游戏库”从单个菜单项改为可展开树状游戏导航。

#### 目标结构

```text
总览

游戏库
├── 全部游戏
├── 未开始
├── 游玩中
└── 已通关

发现候选
截图箱
时间线
设置
```

分类节点下面需要展示对应游戏列表。

建议结构：

```text
游戏库
├── 全部游戏
│   ├── 艾尔登法环
│   └── 空洞骑士
├── 未开始
│   └── ...
├── 游玩中
│   └── ...
└── 已通关
    └── ...
```

#### 任务内容

1. `Sidebar` 中读取游戏列表。
2. 按状态分组：
   - 全部游戏：所有游戏
   - 未开始：`not_started`
   - 游玩中：`in_progress`
   - 已通关：`completed`
3. 支持展开/收起 `游戏库`。
4. 支持展开/收起每个分类。
5. 点击分类进入对应游戏库筛选页。
6. 点击具体游戏进入 `/games/:gameId`。
7. 当前详情页对应的游戏在左侧高亮。

#### UI 要求

- 游戏名称过长时截断显示。
- 分类下没有游戏时，不展示空列表，或显示弱提示“暂无”。
- 侧边栏可滚动，避免游戏多时撑破页面。
- 游戏条目视觉层级要弱于主导航，不能和“总览/截图箱/设置”同级抢视觉。

#### 验收标准

- 左侧 `游戏库` 可以展开/收起。
- 分类可以展开/收起。
- 分类下显示正确游戏。
- 点击游戏能进入详情页。
- 当前游戏在左侧有 active 样式。
- 游戏多时左侧仍可滚动。
- 不影响总览、截图箱、时间线、设置等主导航。

### 任务 C：游戏库页面降级为分类辅助页

#### 目标

`Games.tsx` 不再作为主体验中心，而是作为分类浏览和管理辅助页。

#### 路由建议

支持以下访问方式：

```text
/games
/games?status=not_started
/games?status=in_progress
/games?status=completed
```

#### 任务内容

1. 读取 URL query 中的 `status`。
2. 根据 `status` 初始化筛选条件。
3. 从左侧点击分类时，跳转到对应 query。
4. 页面标题根据筛选变化：
   - 全部游戏
   - 未开始
   - 游玩中
   - 已通关
5. 保留现有添加、编辑、删除、启用/停用功能。
6. 游戏列表中点击游戏仍进入详情页。

#### 验收标准

- `/games?status=in_progress` 只显示游玩中游戏。
- `/games?status=completed` 只显示已通关游戏。
- 从左侧分类跳转后，页面筛选状态正确。
- 原有添加游戏功能仍可用。
- 原有编辑游戏功能仍可用。
- 原有删除游戏功能仍可用。

### 任务 D：游戏详情页信息层级整理

#### 目标

不重写全部详情页，只整理信息优先级，让它更像“游戏档案页”。

#### 顶部区域必须展示

- 游戏封面或默认占位背景
- 游戏名称
- 游戏状态
- 安装状态
- 总游玩时间
- 最近游玩时间
- 启动游戏按钮
- 标记已通关按钮

#### 下方区域建议顺序

1. Session 历史
2. 最近截图
3. 游戏统计
4. 可执行文件路径
5. 游戏备注

#### 任务内容

1. 保留现有启动按钮逻辑。
2. 保留现有通关确认逻辑。
3. 保留现有安装状态显示。
4. 调整布局，让顶部头图区更清晰。
5. 最近截图缩略图必须正常展示。
6. Session 历史应比 exe 信息更靠前。
7. exe 路径信息保留，但不作为视觉主角。

#### 验收标准

- 打开任意游戏详情页，第一屏能看到启动按钮和状态信息。
- 安装状态为 missing/removed 时，历史记录仍能查看。
- Session 历史位置清晰。
- 最近截图能展示缩略图。
- exe 路径仍可查看。
- 页面不再像纯技术详情页，而更像游戏档案页。

### 任务 E：状态自动流转检查

#### 目标

确认状态流转符合产品规则。

#### 状态规则

- 从未产生有效 Session：`not_started`
- 第一次产生有效 Session 后：自动变为 `in_progress`
- 用户手动确认通关：变为 `completed`
- `completed` 后再次游玩，不自动回退

#### 任务内容

1. 检查 `sessionRepository` 或进程监听创建 Session 的逻辑。
2. 确认创建有效 Session 后，如果游戏状态是 `not_started`，更新为 `in_progress`。
3. 确认不会把 `completed` 改回 `in_progress`。
4. 检查游戏详情页“标记已通关”按钮只在合适状态显示。

#### 验收标准

- 新游戏首次启动并生成 Session 后，状态自动变为游玩中。
- 已通关游戏再次生成 Session 后，仍保持已通关。
- 未开始游戏详情页不显示“已通关”误导性状态。
- 游玩中游戏可以手动标记为已通关。

## 5. 禁止修改

本 Sprint 明确禁止以下行为：

### 不要改数据库结构

本次不做新的 migration。

### 不要改截图生命周期

不要动：

- `pending`
- `classified`
- `trashed`
- `deleted`
- 回收站逻辑
- 永久删除逻辑

### 不要改进程监听逻辑

不要动：

- 轮询频率
- 启动判定
- 结束判定
- Session 恢复逻辑

### 不要改游戏启动后端

不要做：

- 启动参数
- Mod 管理
- 多平台启动
- 启动前脚本

### 不要做 Steam 功能

只借鉴左侧库导航，不要加入：

- 商店
- 社区动态
- 成就
- 新闻
- 好友
- 云同步

## 6. 推荐执行顺序

1. 先做任务 A：统一 3 状态显示。
2. 再做任务 B：左侧树状游戏库导航。
3. 再做任务 C：游戏库页面 query 筛选。
4. 再做任务 D：游戏详情页层级整理。
5. 最后做任务 E：状态自动流转检查。

每完成一个任务，都要运行：

```bash
npm run typecheck
```

最终完成后运行：

```bash
npm run build
```

## 7. 最终验收清单

本 Sprint 完成后，必须满足：

1. 左侧游戏库是树状导航。
2. 左侧分类包括全部游戏、未开始、游玩中、已通关。
3. 左侧分类下能显示对应游戏。
4. 点击游戏进入详情页。
5. 游戏库页面支持 status query 筛选。
6. 游戏详情页第一屏突出游戏档案信息和启动按钮。
7. 游戏状态前端只剩 3 种。
8. 已通关不会被自动回退。
9. 截图箱现有功能不被破坏。
10. 游戏启动现有功能不被破坏。
11. `npm run typecheck` 通过。
12. `npm run build` 通过。
