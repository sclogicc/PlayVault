# PlayVault 沉浸式画廊 UI 设计基线

## 1. 设计目标

PlayVault 的界面从“功能工具面板”升级为“个人游戏经历的沉浸式档案馆”。系统应将游戏封面、背景图和截图作为主要视觉内容，同时保持本地数据管理、启动和记录功能的清晰可用。

本次改造以用户确认的“沉浸式画廊”参考图为视觉方向，保留现有页面结构与左侧导航，不新增商店、社交、成就或下载管理等超出产品范围的模块。

## 2. 视觉语言

| 维度 | 设计规则 |
|---|---|
| 色彩 | 使用层次丰富的蓝黑色基底；以紫罗兰作为主交互色，以青绿色表示成功和进行中状态，以琥珀色表示需要注意的提示。 |
| 内容氛围 | 游戏详情背景图可作为局部氛围层；使用暗色渐变遮罩，确保文本和操作始终清晰可读。 |
| 容器 | 采用较大的圆角、低对比度半透明表面和柔和阴影；避免连续使用生硬的描边。 |
| 排版 | 页面标题突出，辅助文字降低对比度；数据采用等宽数字或明确的字重层级，以便快速浏览。 |
| 动效 | 交互状态使用 150–250ms 的透明度、阴影和位移过渡；避免影响录入、批量操作和信息阅读的装饰性动画。 |

## 3. 页面改造原则

| 页面 | 重点改造 |
|---|---|
| 左侧导航 | 深色半透明导航栏；加强当前页面高亮、图标和计数信息；保持既有信息架构。 |
| 总览 | 用“继续游玩”和近期记录建立首屏焦点；统计卡片降低边界感；待整理截图作为次级任务入口。 |
| 游戏库 | 强化封面网格、悬停信息、主次操作；让游戏封面成为列表浏览的主要锚点。 |
| 游戏详情 | 以背景图和封面组成档案头图；在首屏集中展示启动、状态、时长、最近游玩和安装状态。 |
| 截图箱 | 以画廊网格为主；筛选和批量操作固定在清晰的工具栏中；预览与状态标签保持克制。 |
| 时间线、发现、设置 | 继承统一表面、分区标题、表单控件与空状态设计，避免单独设计造成割裂。 |

## 4. 不变约束

- 不修改业务数据模型、IPC 通道和页面路由。
- 不改变左侧游戏库的现有导航信息架构。
- 所有交互状态必须满足键盘焦点可见和文字对比度清晰的基本可用性要求。
- UI 改造不引入在线服务、外部图片依赖或云端功能。
