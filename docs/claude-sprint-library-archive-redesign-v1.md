# Sprint目标

本次 Sprint 的目标是把 `PlayVault` 从“游戏列表页工具”推进到“以游戏详情为中心的个人游戏档案库”第一阶段。

本次只完成以下 4 个可独立验证的小任务：

1. **游戏状态系统收敛**
   把游戏状态统一为：
   - `未开始`
   - `游玩中`
   - `已通关`

2. **游戏记录与安装状态分离**
   即使本地游戏文件被删除，游戏记录仍然保留；
   但启动按钮会变为不可用。

3. **游戏详情页升级为核心页面**
   顶部头图区 + 启动按钮 + 已通关确认按钮 + 下方档案信息区。

4. **左侧游戏库改为树状导航**
   借鉴 Steam Library 的信息架构，但不复制 Steam 的平台功能。

本次 **不重构整个截图系统**，只允许为游戏详情页补充最小截图信息展示能力。

---

# 本次修改范围

## 任务包 A：游戏状态模型重构

目标：
- 从旧的 6 状态收敛到 3 状态

## 任务包 B：安装状态与启动能力

目标：

- 支持从游戏详情页启动主 `exe`

## 任务包 C：左侧库导航重构

目标：
- 左侧 `游戏库` 改为树状导航
- 分类节点承担导航作用
- 点击游戏后进入详情页

## 任务包 D：游戏详情页重构

目标：
- 游戏详情页成为主页面
- 展示头图区、统计信息、Session 历史、截图摘要、备注、路径、安装状态

## 任务包 E：截图模块本次最小调整

目标：
- 只为详情页提供截图摘要和缩略图基础支持
- 不在本 Sprint 内实现截图箱回收站重构

# 数据库修改

## 1. `games` 表修改

### 新增字段
- `status`
  建议存储机器值：
  - `not_started`
  - `in_progress`
  - `completed`

- `install_status`
  建议值：
  - `installed`
  - `missing`

- `completed_at`
  可空，用户确认已通关时写入时间

### 说明
- `status` 表示玩家经历状态
- `install_status` 表示本地文件是否仍然可启动
- 两者必须分离

---

## 2. `game_executables` 表修改

### 新增字段
- `file_path`
  用于保存真实可执行文件完整路径

- `is_primary`
  `0 / 1`
  用于标记主启动 `exe`

### 说明
- 启动游戏必须依赖完整路径
- 自动计时仍可继续主靠 `exe_name`
- 但 UI 的“启动游戏”按钮必须优先使用 `is_primary = 1` 的记录

---

## 3. `sessions` 表本次不新增业务表，但允许继续沿用现有增强字段

如果当前已存在以下字段，则保留，不做回退：
- `end_reason`
- `process_path`
- `created_at`
- `updated_at`

---

## 4. `screenshots` 表本次不做生命周期重构

本 Sprint 不新增“回收站”状态字段，不调整主状态语义。
本次只允许补足“详情页截图摘要”和“缩略图可展示所需字段/读取逻辑”。

---

## 5. 迁移方案

### `games.status` 迁移规则

旧值迁移为新值：

- `未开始` -> `not_started`
- `游玩中` -> `in_progress`
- `已通关` -> `completed`
- `搁置` -> `in_progress`
- `弃坑` -> `in_progress`
- `已全成就` -> `completed`

### `games.install_status`

- 默认写入 `installed`

### `game_executables.file_path`

- 如果现有 `install_path_hint` 存的是完整 `.exe` 路径，则迁移到 `file_path`
- 否则留空，等待后续用户修正或目录扫描补全

### `game_executables.is_primary`

- 若某游戏只有一个 `exe`，则自动设为主 `exe`
- 若多个 `exe`，默认第一个设为主 `exe`

# 功能实现规则

## 游戏状态变化规则

### 1. `未开始 -> 游玩中`
自动发生。

条件：
- 该游戏第一次产生有效 `session`

要求：
- 不需要用户手动点击
- 一旦发生，不再回退为 `未开始`

### 2. `游玩中 -> 已通关`
手动发生。

条件：
- 用户在游戏详情页点击 `确认已通关`
- 弹出确认后写入状态

要求：
- 系统不自动判断是否通关

### 3. `已通关`
规则：
- 该状态不因为后续继续游玩而自动回退
- 后续若需要“取消已通关”，应作为显式人工操作，不自动变化

---

## 安装状态规则

### `installed`
条件：
- 主 `exe` 路径存在且可访问

### `missing`
条件：
- 主 `exe` 路径为空
- 或路径文件不存在
- 或启动时确认文件已丢失

### 规则要求
- 安装状态变化不能删除游戏记录
- 安装状态只影响“能否启动”
- 不影响：
  - 游戏名称
  - 状态
  - 总时长
  - Session 历史
  - 截图
  - 备注

---

## 启动游戏规则

### 启动依据
- 优先使用 `is_primary = 1` 的 `game_executables.file_path`

### 启动前检查
- 路径不能为空
- 文件必须存在

### 启动后行为
- 正常启动后，由既有自动计时系统捕获进程并产生 `session`
- 启动动作本身不直接写入 `session`
- 仍由进程监听负责生成记录

### 异常处理
- 若路径不存在：
  - 启动失败
  - 更新安装状态为 `missing`
  - 前端提示“游戏未安装或路径失效”

---

## 截图展示规则（本 Sprint）

- 截图详情或缩略图必须可预览
- 详情页展示“最近截图”时，优先展示已归类到该游戏的截图
- 本 Sprint 不调整截图忽略逻辑语义
- 本 Sprint 不实现截图回收站

# 验收标准

## 任务包 A：状态系统
1. 数据库中游戏状态只保留 3 种有效值：
   - `not_started`
   - `in_progress`
   - `completed`
2. 已有旧状态数据可以成功迁移
3. 第一次产生有效 `session` 后，游戏状态自动变成 `in_progress`
4. 点击“确认已通关”后，状态变成 `completed`
5. 通关后再次游玩，状态不会自动回退

---

## 任务包 B：安装状态与启动
1. 每个游戏可拥有独立安装状态字段
2. 本地文件存在时，详情页启动按钮可用
3. 本地文件缺失时，详情页启动按钮禁用
4. 点击启动按钮时，能启动主 `exe`
5. 启动成功后，既有自动计时系统能生成 `session`
6. 删除本地游戏文件后，游戏历史仍可查看

---

## 任务包 C：左侧库导航
1. 左侧 `游戏库` 可展开/收起
2. 可见分类节点：
   - 全部游戏
   - 未开始
   - 游玩中
   - 已通关
3. 分类下可展示游戏名列表
4. 点击游戏后能进入对应详情页
5. 不破坏现有主导航结构

---

## 任务包 D：游戏详情页
1. 详情页顶部能显示：
   - 游戏名
   - 状态
   - 安装状态
   - 总时长
   - 最近游玩时间
   - 启动按钮
   - 通关确认按钮
2. 下方能显示：
   - Session 历史
   - 基础统计
   - 最近截图
   - 备注
   - 主 `exe` 路径
3. 详情页可以作为主要浏览页面使用

---

## 任务包 E：截图最小调整
1. 截图箱中图片缩略图可以显示
2. 游戏详情页可展示最近截图缩略图
3. 不因为本次修改破坏现有截图入库和归类逻辑

# 禁止修改

以下内容在本 Sprint 中明确禁止修改：

## 1. 不要重构整个截图系统
禁止：
- 回收站完整实现
- `已忽略 -> 回收站` 全链路重做
- 永久删除流程重做
- 截图状态体系整体翻新

这些属于下一个 Sprint。

## 2. 不要改自动计时基本口径
禁止加入：
- 失焦暂停
- 最小化暂停
- 无输入暂停
- 基于窗口焦点的复杂逻辑

## 3. 不要把产品做成启动器平台
禁止加入：
- 启动参数管理
- 多平台启动聚合
- Mod 管理
- 启动前脚本系统

## 4. 不要破坏已有扫描与候选发现流程
禁止：
- 删除已有目录扫描机制
- 删除候选确认入库流程
- 改成复杂 AI 识别

## 5. 不要把“删除本地文件”理解成“删除游戏档案”
严禁：
- 因路径失效删除 `Game`
- 因路径失效删除 `Session`
- 因路径失效删除截图记录

## 6. 不要一次性改完所有页面
本 Sprint 只允许重点修改：
- 左侧库导航
- 游戏详情页
- 状态模型
- 启动按钮
- 最小截图预览能力

不要同时大改：
- 总览
- 时间线
- 设置全量结构
- 截图箱完整生命周期

# 建议执行顺序

为了让 Claude Code 更容易稳定完成，建议按下面顺序逐项实现并验证：

1. **数据库迁移**
   状态收敛、安装状态、主 `exe`、路径字段

2. **后端逻辑**
   自动状态流转、安装状态检测、启动游戏能力

3. **左侧导航结构**
   树状库导航、分类与游戏跳转

4. **游戏详情页**
   头图区、按钮、统计区、路径与状态区

5. **截图最小展示修复**
   缩略图可见、详情页截图摘要

这样每一步都可以单独验证，不需要一次性重构整个项目。
