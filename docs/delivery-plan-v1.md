# PlayVault 交付实施计划 v1

## 1. 文档用途

本文档不是技术实现细节文档，而是面向开发者与 AI 代码生成工具的交付计划。  
它回答的是“先做什么、后做什么、每一阶段做到什么算完成”。

## 2. 推荐交付形态

从需求特征看，PlayVault v1 最适合做成：

- Windows 桌面应用
- 本地数据库
- 本地文件系统监听
- 后台常驻能力

原因：

- 需要监听本机进程
- 需要监听本地截图目录
- 需要托盘与开机自启动
- 需要长期静默运行

因此，不建议把 v1 定位成纯网页系统。

## 3. 建议开发阶段

### 阶段 1：基础骨架

目标：

- 建立应用壳
- 建立本地数据库
- 建立基础页面结构

产出：

- 可启动的桌面应用
- 总览、游戏库、截图箱、设置页基础导航
- 数据模型落地

完成标志：

- 应用可正常启动
- 页面可切换
- 基础数据可写入与读取

### 阶段 2：游戏库与 Session

目标：

- 先做稳游戏库和自动计时

产出：

- 游戏新增/编辑
- `exe` 绑定
- 进程监听
- 自动创建与结束 `session`
- Session 列表与游戏详情基础信息

完成标志：

- 可为指定游戏配置 `exe`
- 启动游戏后能生成 `session`
- 退出游戏后能正确结束
- 游戏详情可展示总时长和记录列表

### 阶段 3：截图监听与待整理

目标：

- 打通截图发现和截图归类主链路

产出：

- NVIDIA 截图目录设置
- 文件监听
- 截图入库
- 时间匹配 `session`
- 自动归类
- 待整理列表

完成标志：

- 新截图可被发现
- 单候选场景可自动归类
- 不确定场景进入待整理

### 阶段 4：截图手动管理

目标：

- 让截图系统真正可用

产出：

- 手动归类
- 标记忽略
- 打开文件位置
- 手动复制/移动到归档目录
- 游戏详情截图墙

完成标志：

- 用户可整理未识别截图
- 用户能在游戏详情页浏览对应截图

### 阶段 5：总览、时间线与收尾

目标：

- 完成主要用户感知价值

产出：

- 今日/周/月统计
- 最近在玩的游戏
- 时间线页面
- 托盘、自启动、导出与备份

完成标志：

- 产品具备日常可用性
- 用户打开应用后能快速感知自己的游玩情况

## 4. 模块拆分

### 4.1 应用壳模块

职责：

- 窗口
- 路由
- 全局状态
- 设置加载

### 4.2 游戏库模块

职责：

- 游戏 CRUD
- 状态管理
- `exe` 绑定
- 标签、别名、文件夹名管理

### 4.3 进程监听模块

职责：

- 轮询或监听本机进程
- 匹配已配置游戏
- 创建和结束 `session`
- 处理异常中断

### 4.4 Session 模块

职责：

- 游玩记录存储
- 时长计算
- 按时间聚合统计

### 4.5 截图监听模块

职责：

- 监听截图目录
- 读取图片元数据
- 图片入库

### 4.6 截图归类模块

职责：

- 时间匹配 `session`
- 自动归类
- 待整理处理
- 手动修正

### 4.7 统计模块

职责：

- 总时长统计
- 今日/周/月统计
- 最近活跃游戏统计

### 4.8 文件操作模块

职责：

- 打开文件位置
- 复制图片
- 移动图片
- 校验路径

## 5. 推荐开发顺序

必须遵守以下顺序：

1. 先数据模型
2. 再游戏库
3. 再 `session`
4. 再截图监听
5. 再截图整理
6. 最后总览与体验优化

原因：

- 总览和时间线都依赖 `session`
- 截图归类依赖 `session`
- 手动整理依赖截图已入库

## 6. AI 开发约束

如果后续交给其他 AI 生成代码，必须强调这些约束：

1. 不得把 v1 做成纯网页应用。
2. 不得去掉 `session`，只保留总时长。
3. 不得默认自动移动原始截图。
4. 不得擅自加入“失焦暂停”或“无输入暂停”逻辑。
5. 不得把截图归类核心逻辑改成依赖文件名。
6. 不得把待整理当成异常分支删除。
7. 不得擅自加入云同步或账号系统。

## 7. 测试重点

### 7.1 计时相关

- 游戏正常启动和退出
- 游戏崩溃
- 游戏重复启动
- 多游戏同时运行
- 停用游戏不再记录

### 7.2 截图相关

- 新截图实时发现
- 截图时间正确读取
- 单候选自动归类
- 多候选进入待整理
- 手动归类后状态更新正确

### 7.3 数据相关

- 删除 `session` 后统计是否同步更新
- 修改游戏名称后是否影响历史数据
- 移动或删除原图后系统是否能识别失效路径

## 8. 风险控制

### 8.1 容易返工的点

- 计时规则改口径
- 数据模型不存 `session`
- 截图一上来就做自动搬运
- 页面先做得太花，底层逻辑不稳

### 8.2 控制办法

- 优先实现产品主链路
- 先做正确的数据模型，再做统计与展示
- 默认所有危险文件操作都需要人工触发
- 对每个模块定义明确完成标准

## 9. 里程碑验收

### 里程碑 A：计时可用

验收标准：

- 可以配置游戏
- 可以自动记录 `session`
- 可以查看总时长

### 里程碑 B：截图可用

验收标准：

- 可以监听截图目录
- 可以自动归类部分截图
- 可以手动整理剩余截图

### 里程碑 C：产品可日常使用

验收标准：

- 总览、游戏详情、截图箱、时间线均可使用
- 用户能持续一周以上稳定使用
- 核心流程无需依赖命令行操作

## 10. 最终交付清单建议

v1 最终至少应包含：

- 可运行桌面应用
- 本地数据库
- 基础设置能力
- 游戏库
- 自动计时
- 截图监听
- 截图待整理
- 手动归类
- 统计总览
- 时间线
- 数据导出或备份
