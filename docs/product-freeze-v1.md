# PlayVault 产品冻结清单 v1

## 1. 文档用途

本文档用于冻结 PlayVault v1 的关键产品决策。  
后续无论是人工开发还是交给其他 AI 生成代码，都必须以本清单为最高优先级约束之一。

## 2. 已冻结的产品定义

1. PlayVault 是 `Windows 本地桌面应用`，不是纯网页应用。
2. PlayVault 是 `单用户本地工具`，不做账号系统。
3. PlayVault 的核心定位是：
   本地游戏游玩记录 + 游戏库管理 + NVIDIA 截图半自动归类。

## 3. 已冻结的核心规则

### 3.1 自动计时规则

规则固定如下：

- 游戏进程启动即开始计时
- 游戏进程退出即结束计时
- 只要进程活着就持续计时

v1 禁止擅自改为以下逻辑：

- 失焦暂停
- 无输入暂停
- 后台暂停

### 3.2 游戏识别规则

规则固定如下：

- 按 `exe` 文件名为主识别游戏
- 一个游戏允许绑定多个 `exe`
- 冲突时必须通过人工修正，不自动猜测

### 3.3 Session 规则

规则固定如下：

- 系统必须保存每次游玩的 `session`
- 不允许只保留累计总时长
- 所有统计结果都由 `session` 汇总得到

### 3.4 截图归类规则

规则固定如下：

- 截图来源以 NVIDIA 截图目录为主
- 归类依据为“截图时间匹配进行中的 `session`”
- 不使用文件名作为核心归类依据
- 不使用图像内容 AI 识别作为 v1 方案
- 多候选命中时，一律进入待整理
- 无候选命中时，一律进入待整理

### 3.5 截图文件操作规则

规则固定如下：

- 默认只建立截图索引
- 默认不自动移动原始截图
- 用户手动归档时，默认推荐复制
- 移动原始文件必须是明确的手动操作

## 4. 已冻结的 v1 范围

### 4.1 v1 必做

1. 游戏库管理
2. `exe` 绑定
3. 自动生成 `session`
4. 总览统计
5. NVIDIA 截图目录监听
6. 自动归类新截图
7. 待整理截图列表
8. 手动归类截图
9. 游戏详情页
10. 时间线
11. 托盘运行

### 4.2 v1 不做

1. 历史截图批量导入主链路
2. 自动抓取游戏封面
3. 云同步
4. 多设备同步
5. 账号系统
6. 社交功能
7. 自动识别通关
8. 成就平台同步
9. 图像内容 AI 识别游戏
10. 复杂图片编辑器

### 4.3 P1 范围

1. 开机自启动
2. 更强的数据导出
3. 更强的批量截图整理
4. 路径级识别增强

## 5. 已冻结的数据与目录口径

1. 截图归档目录结构采用“按游戏”，v1 不加“年月”子目录。
2. 截图来源目录采用全局配置，不给单个游戏单独配置来源目录。
3. 数据导出优先提供完整数据库备份。
4. 游戏状态固定为：
- 未开始
- 游玩中
- 已通关
- 搁置
- 弃坑
- 已全成就

## 6. 已冻结的交互原则

1. 自动优先
2. 不确定不硬判
3. 安全优先
4. 明细优先
5. 本地优先

## 7. 开发约束

后续开发者或 AI 不得做以下变更：

1. 不得把产品改成纯网页站点。
2. 不得删除 `session` 模型，只保留总时长。
3. 不得默认自动移动 NVIDIA 原始截图。
4. 不得把截图归类主逻辑改为文件名匹配。
5. 不得在多候选场景下自动猜测截图归属。
6. 不得将待整理视为异常状态并省略该页面。
7. 不得将历史截图整理强行塞进 v1 主链路。
