# PlayVault 下一阶段开发规划 v2

## 1. 文档目标

本文档根据当前真实使用反馈，重新制定 PlayVault 下一阶段开发任务目标和开发规划。

本规划面向 Claude Code 或其他编码执行者使用。它不是产品讨论稿，而是开发执行路线图。

核心原则：

- 优先修复当前真实使用中的基础缺陷
- 每个 Sprint 范围有限、可独立验证
- 不一次性重构整个系统
- 保持 PlayVault 的定位：个人本地游戏档案库

## 2. 最新产品目标

PlayVault 当前阶段的目标是从“本地游戏计时工具”升级为：

`一个长期保存个人本地单机游戏经历的软件`

核心价值必须围绕三件事：

1. 自动记录：游戏启动后可靠生成 Session
2. 长期保存：删除游戏文件后记录不丢失
3. 方便回顾：通过详情页、截图、时间线回看过去的游戏经历

## 3. 当前最重要的问题

### 3.1 截图箱基础体验不足

当前问题：

- 截图无法正常预览，显示为空白
- 忽略后的截图仍然出现在主要列表中

判断：

- 截图预览是截图箱成立的基础能力，优先级最高
- “忽略”语义需要改为“进入回收站”，不能继续留在主要列表

### 3.2 游戏记录与安装状态分离不够彻底

当前必须明确区分：

- 游戏记录：Game，是长期档案
- 安装状态：Installation，是当前本机文件是否存在、能否启动

规则：

- 删除本地游戏文件不能删除 Game
- 删除本地游戏文件不能删除 Session
- 删除本地游戏文件不能删除 Screenshot
- 路径失效只影响启动按钮和安装状态

### 3.3 游戏状态系统需要收敛

游戏状态只保留：

- 未开始
- 游玩中
- 已通关

规则：

- 未开始：从未产生有效 Session
- 游玩中：第一次产生有效 Session 后自动进入
- 已通关：用户手动确认

### 3.4 游戏库需要从表格升级为导航入口

当前表格适合管理少量数据，但不适合长期回顾。

目标方向：

- 左侧树状游戏库导航
- 右侧游戏详情页承载主要内容
- 游戏列表承担导航职责，不再承担主要展示职责

### 3.5 游戏详情页需要成为核心页面

游戏详情页应成为用户回顾单个游戏经历的主入口。

它应展示：

- 封面
- 游戏名称
- 游戏状态
- 安装状态
- 总游玩时间
- 最近游玩时间
- 启动游戏按钮
- 标记已通关按钮
- Session 历史
- 截图统计与预览
- 游戏备注
- exe 路径

## 4. 开发总优先级

### P0：必须优先完成

1. 修复截图预览
2. 重构截图状态与回收站

原因：

- 当前截图箱处于基础不可用状态
- 截图整理是 PlayVault 与纯计时器拉开差异的关键能力

### P1：核心架构修正

1. 简化游戏状态为 3 状态
2. 分离安装状态与游戏记录
3. 实现游戏启动按钮

原因：

- 这些决定长期数据是否可信
- 这些决定删除本地游戏后能否继续回顾
- 启动按钮形成“启动游戏 -> 自动记录 Session”的闭环

### P2：体验结构升级

1. Steam 式左侧树状游戏库导航
2. 游戏详情页升级为核心档案页

原因：

- 游戏数量增加后，表格模式会越来越难用
- 详情页应成为个人游戏经历的主要回顾入口

### P3：后续增强

1. 本地游戏自动发现增强
2. 未知进程待确认
3. 路径重新定位
4. 安装状态历史记录

原因：

- 这些能提升效率，但不是当前最紧急的基础可用性问题

## 5. Sprint 拆分

## Sprint 1：截图箱基础可用性修复

### Sprint 目标

把截图箱从“扫描结果列表”升级为基础可用的截图整理流程。

### 本次修改范围

- 修复截图缩略图预览
- 重构截图状态语义
- 将“已忽略”改为“回收站”
- 支持恢复
- 支持永久删除
- 永久删除后不再展示

### 涉及模块

- 数据库
- 截图仓储
- 截图 IPC
- 截图箱页面
- 图片文件读取与展示

### 数据库修改

#### `screenshots.status`

统一为以下状态：

- `pending`：待整理
- `classified`：已归类
- `trashed`：回收站
- `deleted`：永久删除后的逻辑删除状态

旧状态迁移建议：

- `pending` -> `pending`
- `classified` -> `classified`
- `ignored` -> `trashed`

#### 新增字段

- `deleted_at`：永久删除时间，可空
- `updated_at`：更新时间

如当前已有 `hash`、`file_path`、`game_id`、`session_id`，继续保留。

### 后端/桌面层任务

1. 提供截图文件可预览能力
   - 支持把本地图片路径转换为前端可显示的安全资源地址
   - 不允许前端直接猜测本地文件访问方式

2. 实现截图状态切换
   - 待整理 -> 已归类
   - 待整理 -> 回收站
   - 回收站 -> 待整理
   - 回收站 -> deleted

3. 永久删除逻辑
   - 默认只做数据库逻辑删除
   - 不物理删除原图，除非后续单独设计
   - `deleted` 状态截图不再出现在任何主要列表

4. 扫描去重
   - 已经是 `deleted` 的截图后续扫描不应重新进入待整理

### 前端任务

1. 截图箱标签改为：
   - 全部
   - 待整理
   - 已归类
   - 回收站

2. 展示规则：
   - 全部：展示 `pending` + `classified`
   - 待整理：展示 `pending`
   - 已归类：展示 `classified`
   - 回收站：展示 `trashed`
   - 不展示 `deleted`

3. 操作规则：
   - 待整理中可归类、可移入回收站
   - 已归类中可查看、可重新归类、可移入回收站
   - 回收站中可恢复、可永久删除

4. 缩略图必须正常显示

### 验收标准

1. 截图箱中的截图能正常预览
2. 点击忽略后，截图进入回收站
3. 回收站截图不出现在“全部”列表
4. 回收站中的截图可以恢复到待整理
5. 回收站中的截图可以永久删除
6. 永久删除后的截图不再出现在任何列表
7. 重新扫描时，已永久删除截图不会再次出现

### 禁止修改

- 不做 AI 图像识别
- 不做图片编辑器
- 不做云图库
- 不物理删除原图，除非用户后续明确要求

## Sprint 2：游戏状态与安装状态分离

### Sprint 目标

让 Game 成为长期档案对象，并把“玩家经历状态”和“本地安装状态”彻底分离。

### 本次修改范围

- 游戏状态简化为 3 状态
- 增加安装状态
- 增加路径失效处理
- 增加重新定位入口的基础接口

### 涉及模块

- 数据库
- Game 仓储
- GameExecutable 仓储
- Session 创建逻辑
- 游戏详情页

### 数据库修改

#### `games.status`

统一机器值：

- `not_started`
- `in_progress`
- `completed`

旧状态迁移：

- `未开始` -> `not_started`
- `游玩中` -> `in_progress`
- `已通关` -> `completed`
- `搁置` -> `in_progress`
- `弃坑` -> `in_progress`
- `已全成就` -> `completed`

#### `games` 新增字段

- `install_status`
  - `installed`
  - `missing`
  - `removed`
- `completed_at`
- `cover_image_path`

#### `game_executables` 新增或确认字段

- `full_path`
- `is_primary`
- `last_verified_at`

如当前已有 `install_path_hint`，后续可迁移到 `full_path`。

### 后端/桌面层任务

1. Session 创建后自动更新游戏状态
   - 如果游戏状态为 `not_started`，创建有效 Session 后自动变为 `in_progress`
   - 如果游戏状态为 `completed`，不自动回退

2. 安装状态检测
   - 检查主 exe 的 `full_path` 是否存在
   - 存在则 `installed`
   - 不存在则 `missing`

3. 已移除状态
   - 当用户明确标记“已移除”时，设置为 `removed`
   - 不能删除 Game、Session、Screenshot

4. 重新定位接口
   - 支持用户选择新的 exe 路径
   - 更新主 exe 的 `full_path`
   - 更新 `install_status = installed`

### 前端任务

1. 游戏详情页同时显示：
   - 游戏状态
   - 安装状态

2. 安装状态显示规则：
   - `installed`：已安装
   - `missing`：路径失效
   - `removed`：已移除

3. 当安装状态不是 `installed` 时：
   - 启动按钮禁用
   - 显示“重新定位游戏路径”入口

4. 通关按钮：
   - 只在 `in_progress` 状态下显示“标记为已通关”
   - 点击后确认
   - 写入 `completed` 和 `completed_at`

### 验收标准

1. 游戏状态只剩 3 种有效值
2. 第一次有效 Session 后，游戏自动从未开始变为游玩中
3. 用户可以手动标记已通关
4. 已通关游戏继续游玩不会自动回退为游玩中
5. 本地 exe 删除后，游戏记录仍然存在
6. 本地 exe 删除后，启动按钮不可用
7. 路径重新定位后，启动按钮恢复可用

### 禁止修改

- 不恢复搁置、弃坑、全成就为主状态
- 不因为路径失效删除游戏记录
- 不因为路径失效删除 Session
- 不因为路径失效删除截图记录

## Sprint 3：启动游戏闭环

### Sprint 目标

实现从 PlayVault 直接启动本地游戏，并保持自动计时仍由进程监听负责。

### 本次修改范围

- 游戏详情页启动按钮
- 主 exe 启动逻辑
- 启动前路径校验
- 启动失败后的安装状态更新

### 涉及模块

- GameExecutable
- 游戏详情页
- Electron shell / child process 启动逻辑
- 安装状态检测
- 进程监听服务

### 后端/桌面层任务

1. 启动主 exe
   - 优先使用 `is_primary = 1` 的 `full_path`
   - 路径存在才允许启动

2. 启动失败处理
   - 如果文件不存在，更新 `install_status = missing`
   - 返回明确错误给前端

3. 启动后不直接创建 Session
   - Session 仍由进程监听模块创建
   - 启动按钮只负责打开 exe

### 前端任务

1. 游戏详情页头部提供主按钮：`启动游戏`
2. 按钮可用条件：
   - 存在主 exe
   - `full_path` 有效
   - 安装状态为 `installed`
3. 启动失败时显示错误提示

### 验收标准

1. 点击启动按钮可以启动本地 exe
2. 启动后自动计时系统可以生成 Session
3. 路径失效时启动按钮不可用或启动失败后自动标记 missing
4. 启动失败不会创建 Session

### 禁止修改

- 不做启动参数管理
- 不做 Mod 管理
- 不做 Steam/Epic/GOG 启动整合
- 不让启动按钮直接写 Session

## Sprint 4：Steam 式库导航与游戏详情页升级

### Sprint 目标

把游戏库从“表格管理页”升级为“左侧树状导航 + 右侧游戏档案详情页”。

### 本次修改范围

- 左侧导航重构
- 游戏详情页头图区
- 详情页信息区
- 表格页降级为辅助视图

### 涉及模块

- Sidebar
- AppLayout
- Games 页面
- GameDetail 页面
- Game hooks
- Session hooks
- Screenshot hooks

### 左侧导航设计

游戏库节点结构：

- 游戏库
  - 全部游戏
  - 未开始
  - 游玩中
  - 已通关

要求：

- 分类可展开/收起
- 分类下展示游戏名称
- 点击游戏进入详情页
- 游戏列表只是导航，不再承担主要展示职责

### 游戏详情页设计

顶部三分之一区域展示：

- 封面或默认背景
- 游戏名称
- 游戏状态
- 安装状态
- 总游玩时间
- 最近游玩时间
- 启动游戏按钮
- 标记已通关按钮

下方区域展示：

- Session 历史
- 游玩时间统计
- 截图统计
- 最近截图
- 游戏备注
- exe 路径
- 重新定位入口

### 验收标准

1. 左侧游戏库可以展开分类
2. 点击分类可以看到该分类游戏
3. 点击游戏进入详情页
4. 详情页顶部包含启动按钮和状态信息
5. 详情页下方展示 Session、截图、备注、路径信息
6. 即使安装状态为 missing 或 removed，详情页仍可完整展示历史记录

### 禁止修改

- 不复制 Steam 商店功能
- 不做社区动态
- 不做成就系统
- 不做平台同步

## Sprint 5：本地游戏自动发现增强

### Sprint 目标

在核心记录和截图系统稳定后，增强本地游戏目录扫描与候选确认体验。

### 本次修改范围

- 游戏根目录扫描
- exe 过滤规则
- 候选游戏确认
- 加入游戏库
- 绑定主 exe 和完整路径

### 涉及模块

- scan_roots
- discovered_executables
- scanner
- scorer
- Discover 页面
- Game / GameExecutable 仓储

### 扫描规则

- 用户配置游戏根目录
- 扫描一级和有限深度子目录
- 只扫描 `.exe`
- 过滤明显非游戏程序：
  - `uninstall.exe`
  - `setup.exe`
  - `config.exe`
  - `updater.exe`
  - `patch.exe`
- 生成候选列表，由用户确认后加入游戏库

### 验收标准

1. 用户可以配置游戏根目录
2. 扫描后生成候选 exe
3. 候选可加入游戏库
4. 加入时写入主 exe 和完整路径
5. 忽略的候选不会反复打扰用户

### 禁止修改

- 不做 AI 游戏识别
- 不做图像识别
- 不做全盘扫描
- 不做联网元数据抓取

## 6. 全局禁止扩展项

以下功能在当前阶段全部禁止：

- Steam 同步
- Epic/GOG 同步
- 成就系统
- 云同步
- Mod 管理
- 社交功能
- 游戏推荐
- 商店入口
- AI 图像识别
- 复杂启动参数系统
- 复杂多用户系统

## 7. 推荐执行顺序

Claude Code 应按以下顺序执行，不要跨 Sprint 大范围混改：

1. Sprint 1：截图箱基础可用性修复
2. Sprint 2：游戏状态与安装状态分离
3. Sprint 3：启动游戏闭环
4. Sprint 4：Steam 式库导航与游戏详情页升级
5. Sprint 5：本地游戏自动发现增强

每个 Sprint 完成后都必须单独验证，再进入下一个 Sprint。

## 8. 总结

当前最重要的不是继续扩功能，而是把 PlayVault 的核心体验做稳：

- 截图能看、能整理、能恢复
- 游戏记录和安装文件彻底分离
- 游戏状态简单可信
- 启动游戏和自动记录形成闭环
- 游戏库从表格升级为导航
- 游戏详情页成为个人游戏档案核心页面

只要这些完成，PlayVault 才真正从“计时工具”升级为“个人游戏档案馆”。
