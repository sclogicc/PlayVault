# PlayVault 开发任务拆解清单 v1

## 1. 文档用途

本文档用于把 PlayVault v1 的产品需求拆解成可执行的开发任务包，方便交给其他 AI 或开发者按阶段推进。

使用原则：

- 每一轮开发只处理一个明确阶段
- 每一轮都必须有清晰输入、输出和完成标准
- 不允许跳过前置阶段直接做后置界面
- 所有实现均需遵守 `product-freeze-v1.md`

建议配合以下文档一起使用：

- `docs/product-freeze-v1.md`
- `docs/ai-build-brief-v1.md`
- `docs/prd-v1.md`
- `docs/delivery-plan-v1.md`
- `docs/ui-ux-spec-v1.md`

## 2. 总体开发顺序

建议严格按照以下顺序推进：

1. 应用基础骨架
2. 数据模型与本地存储
3. 游戏库管理
4. 进程监听与 `session`
5. 截图监听与截图入库
6. 截图归类与待整理
7. 统计总览与时间线
8. 托盘、导出、收尾优化

原因：

- 截图归类依赖 `session`
- 总览统计依赖 `session`
- 游戏详情依赖游戏、`session`、截图三类数据

## 3. 任务包拆解

### 任务包 1：项目基础骨架

目标：

- 建立可运行的 Windows 桌面应用基础结构
- 建立页面导航骨架
- 建立基础工程目录

输入：

- `docs/product-freeze-v1.md`
- `docs/ai-build-brief-v1.md`
- `docs/ui-ux-spec-v1.md`

任务内容：

1. 初始化桌面应用项目
2. 建立基础页面路由
3. 建立全局布局
4. 建立左侧导航结构
5. 预留总览、游戏库、截图箱、时间线、设置页入口

输出：

- 可启动应用
- 可切换页面的基础界面
- 稳定的项目目录结构

完成标准：

- 应用可以正常启动
- 页面导航可正常切换
- 没有业务功能也能完成基础壳验证

不包含：

- 数据库
- 游戏逻辑
- 截图逻辑

### 任务包 2：数据模型与本地存储

目标：

- 落地核心数据实体
- 建立本地数据库与数据读写层

输入：

- `docs/prd-v1.md`
- `docs/product-freeze-v1.md`

任务内容：

1. 创建 `Game` 数据实体
2. 创建 `GameExecutable` 数据实体
3. 创建 `Session` 数据实体
4. 创建 `Screenshot` 数据实体
5. 创建 `AppSetting` 数据实体
6. 建立本地数据存储方案
7. 建立基础 CRUD 访问层

输出：

- 数据表或数据模型定义
- 本地数据库初始化逻辑
- 基础读写能力

完成标准：

- 可以新增、读取、更新、删除基础数据
- 重启应用后数据仍可保留
- 数据模型字段与 PRD 保持一致

不包含：

- 进程监听
- 页面复杂交互

### 任务包 3：游戏库管理

目标：

- 让用户可以正式管理自己的游戏条目

输入：

- 任务包 1 输出
- 任务包 2 输出

任务内容：

1. 实现游戏列表页
2. 实现新增游戏表单
3. 实现编辑游戏表单
4. 支持配置显示名称
5. 支持配置别名
6. 支持配置状态
7. 支持配置标签
8. 支持配置截图文件夹名
9. 支持绑定一个或多个 `exe`
10. 支持启用/停用游戏监控

输出：

- 可用的游戏库页面
- 可用的游戏新增和编辑功能

完成标准：

- 用户可以完整创建一个游戏条目
- 同一游戏可以绑定多个 `exe`
- 用户可以停用某个游戏
- 页面能展示游戏基础信息

不包含：

- 自动计时
- 截图归类

### 任务包 4：进程监听与 Session 记录

目标：

- 实现 PlayVault 最核心的自动计时能力

输入：

- 任务包 2 输出
- 任务包 3 输出
- `docs/product-freeze-v1.md`

任务内容：

1. 建立本机进程监听机制
2. 匹配已配置的 `exe`
3. 当进程启动时创建进行中的 `session`
4. 当进程退出时结束该 `session`
5. 计算时长
6. 处理意外关闭或异常中断
7. 实现单游戏 `session` 列表展示
8. 实现手动删除异常 `session`

输出：

- 自动生成的游玩记录
- 基础 `session` 列表

完成标准：

- 已配置游戏启动后会自动产生记录
- 退出后记录能正常结束
- 时长计算正确
- 异常情况下不会长期残留错误的进行中记录

不包含：

- 截图监听
- 总览统计

### 任务包 5：截图监听与截图入库

目标：

- 让系统能发现 NVIDIA 新截图并保存到本地索引

输入：

- 任务包 2 输出
- 任务包 4 输出

任务内容：

1. 实现全局 NVIDIA 截图目录设置
2. 实现截图目录监听
3. 发现新增图片文件
4. 读取截图基础元数据
5. 把截图写入本地数据库
6. 标记截图初始状态

输出：

- 可监听的新截图列表
- 本地截图索引数据

完成标准：

- 新图片出现后系统能发现它
- 图片路径和生成时间能被保存
- 截图即使未归类也能被记录

不包含：

- 自动归类
- 截图浏览体验优化

### 任务包 6：截图归类与待整理

目标：

- 打通截图自动归类主链路

输入：

- 任务包 4 输出
- 任务包 5 输出
- `docs/product-freeze-v1.md`

任务内容：

1. 实现“截图时间匹配进行中的 `session`”逻辑
2. 单候选时自动归类到对应游戏
3. 多候选时进入待整理
4. 无候选时进入待整理
5. 实现待整理截图列表
6. 实现手动归类到指定游戏
7. 实现标记忽略
8. 实现打开原文件位置
9. 实现手动复制到归档目录
10. 实现手动移动到归档目录

输出：

- 自动归类逻辑
- 待整理页面
- 手动整理能力

完成标准：

- 大部分新截图可被自动识别或进入待整理
- 用户能手动完成归类
- 系统不会默认自动移动原图

不包含：

- 历史截图批量导入
- 图像内容识别

### 任务包 7：游戏详情页

目标：

- 形成“一个游戏的完整档案页”

输入：

- 任务包 3 输出
- 任务包 4 输出
- 任务包 6 输出

任务内容：

1. 展示游戏基础信息
2. 展示游戏状态、标签、别名
3. 展示总时长
4. 展示最后游玩时间
5. 展示全部 `session`
6. 展示全部截图
7. 展示备注与文件夹名

输出：

- 完整游戏详情页

完成标准：

- 用户能在一个页面中看到该游戏的时长和截图
- 页面能作为日常回看入口使用

### 任务包 8：总览页与统计

目标：

- 给用户一个打开应用后的一眼感知页

输入：

- 任务包 4 输出
- 任务包 6 输出
- 任务包 7 输出

任务内容：

1. 实现今日时长统计
2. 实现本周时长统计
3. 实现本月时长统计
4. 实现每个游戏总时长排行
5. 实现最近在玩的游戏模块
6. 实现待整理截图提醒
7. 实现最近新增截图展示

输出：

- 可用的总览页

完成标准：

- 用户打开应用后能快速知道最近玩了什么
- 统计数据与 `session` 数据一致

### 任务包 9：时间线页面

目标：

- 提供按日期回看游玩历史的能力

输入：

- 任务包 4 输出
- 任务包 6 输出

任务内容：

1. 按日期聚合 `session`
2. 展示每日总时长
3. 展示每日游玩记录列表
4. 关联显示该次游玩截图
5. 支持从时间线跳到游戏详情

输出：

- 时间线页面

完成标准：

- 用户能按天回顾自己的游玩轨迹
- 同一天多个 `session` 展示清晰

### 任务包 10：设置、托盘与数据安全

目标：

- 补齐日常使用所需的系统能力

输入：

- 前面所有任务包输出

任务内容：

1. 设置页完善
2. NVIDIA 来源目录设置
3. 统一归档目录设置
4. 自动扫描开关
5. 托盘运行
6. 数据备份导出
7. 路径有效性校验

输出：

- 可长期使用的基础系统能力

完成标准：

- 应用可最小化到托盘
- 用户能调整关键路径配置
- 用户能导出本地数据备份

不包含：

- 开机自启动
- 云同步

## 5. 给其他 AI 的任务下发模板

建议每次只下发一轮任务，使用以下模板：

### 模板

你现在负责开发 PlayVault 的第 X 轮功能。

必须遵守这些文档：

- `docs/product-freeze-v1.md`
- `docs/ai-build-brief-v1.md`
- `docs/prd-v1.md`
- `docs/development-task-breakdown-v1.md`

本轮只允许实现以下任务包：

- 任务包 X
- 任务包 X

开发要求：

1. 不要擅自扩大范围
2. 不要实现文档明确排除的功能
3. 保持数据模型与 PRD 一致
4. 完成后说明实现了哪些点、未实现哪些点、还有哪些风险

## 6. 每轮开发完成后的检查项

每一轮开发结束后，都应检查：

1. 是否违反 `product-freeze-v1.md`
2. 是否擅自加入额外产品逻辑
3. 是否遗漏任务包中的必做项
4. 是否产生明显耦合或后续返工风险
5. 是否为下一轮留下清晰可接续的结构

## 7. 最终说明

本任务拆解清单的目标不是让开发“一次写完”，而是让 PlayVault v1 能以低返工、低跑偏的方式逐轮落地。

后续如进入 v1.1 或 v2.0，应在本清单基础上另开新版本，不直接混入当前 v1 主链路。
